## What the checks establish

**Fact — root scrolling.** For each route the audit waits for the dock and initial kernel-loading/first-run messages to finish, waits for fonts and an animation frame, reads `document.scrollingElement.scrollHeight/scrollWidth`, and attempts `window.scrollTo(100,100)`. Dimensions must fit the viewport exactly, and the resulting scroll offsets must remain zero. This checks both horizontal and vertical document scrolling even when the root has `overflow:hidden`. Source: [geometry test](../../spikes/scene-acceptance-audit/audit.spec.mjs).

**Assumption — horizontal element scope.** Internal scroll panels are intentional under the [one-scene module map](lecture-module-map.md#product-rule-one-scene). The element test therefore intersects each rendered HTML element's rectangle with its internal clipping/scrolling ancestors, while deliberately ignoring the root's clipping. An unclipped horizontal excursion larger than one CSS pixel fails. Zero-area/hidden elements, SVG internals, screen-reader MathML and `aria-hidden` decoration are excluded. This is a declared operational definition, not a claim that every DOM rectangle is inside the screen or that all inner content fits without panel scrolling.

**Fact — visual qualification.** Playwright's [visible assertion](https://playwright.dev/docs/api/class-locatorassertions#locator-assertions-to-be-visible) establishes rendered-element visibility; it does not certify that a globe remains recognizable behind a covering panel. In the inspected [1280×720 fixture screenshot](../../spikes/scene-acceptance-audit/evidence/fixture-at-1280.png), the station occupies most of the scene and the globe is heavily obscured. The subject's [stage styles](../../spikes/visual-foundation/src/stage.css) use a translucent dark background and backdrop blur for the dock, and [scene styles](../../spikes/visual-foundation/src/stations/scene.css) dim the underlying scene. Therefore the automatic visibility result must not be presented as proof of an unobscured globe. This audit confirms the persistent scene element and orbit switcher; a stronger requirement for globe recognizability remains a visual acceptance question for the owner.

**Fact — isolation.** The replay test calls `browser.newContext`, rather than opening another page in the original context. It seeds only the language preference so the displayed table labels match, and supplies no prior run state, cookies or sample storage. Seeds and parameters are read solely from the URL. The original and replayed table rows are saved in evidence. This follows Playwright's documented [browser-context isolation](https://playwright.dev/docs/browser-contexts). Sources: [replay tests](../../spikes/scene-acceptance-audit/audit.spec.mjs), [recorded rows](../../spikes/scene-acceptance-audit/evidence.json).

**Fact — pending kernels.** `#station/urn` and `#station/bernoulli` display their kernel-in-progress panels in the tested commit. Both are included in the route and keyboard audit. Their success establishes host-shell behavior only; it cannot establish the missing numerical kernel or its future layout. No tested station reports a rendered station alert in the geometry observations. Source: `counts.pendingKernelRoutes`, `counts.stationAlerts` and per-route records in [evidence.json](../../spikes/scene-acceptance-audit/evidence.json).

**Fact — malformed cases.** The test includes bad station escapes `%E0%A4%A` and `%`, unknown station/orbit IDs, and contract-fixture seeds `%E0`, `-1`, `4294967296`, `1.5`, `1e3` and empty text. It checks rendering and uncaught errors rather than importing or asserting a particular parser fallback. That distinction avoids calling an accepted fallback the required scientific seed policy. Source: [malformed-route test and recorded normalized URLs](../../spikes/scene-acceptance-audit/evidence.json).

## Reproduction and limits

**Fact — reproduction.** [The spike README](../../spikes/scene-acceptance-audit/README.md) gives the two-terminal commands. The suite uses the prototype's existing locked Playwright dependency and a dev-server port provided through `PORT`. It does not start the server, patch the subject, download a browser or change shared configuration. The evidence collector extracts the runner's JSON attachments and source/version information; ignored `results/` retains the local full report, traces and failure screenshots if any.

**Assumption — bounded claim.** These are default-parameter desktop observations in one installed Edge browser, one language and reduced motion. They do not exhaust all parameters, seeds, timings, normal-motion transitions, languages, browsers, display scaling, phones or assistive technologies. The three replay cases are explicit examples of the contract-fixture path, not proof of all stations' numerical determinism. Hidden routes lack opener cards by design. Nested content clipping and globe recognizability need visual judgement beyond the automated assertions.

**Fact — harness status.** The task's full `crew check` is a separate check from this explicit Playwright invocation. At this discovery-stage subject commit, configured web/api/acceptance paths do not exist, so the harness reports all steps skipped and `verified:false`. The 14 browser passes above come from the independent invocation, not from claiming that skipped harness steps passed. The repository's owner-billing CI restriction is recorded in [captain guidance #27](https://github.com/GredesCerber/matstat-lab/issues/27); this work does not bypass it or provide its own successful GitHub check status.

## Position

**Assumption — recommendation.** Keep this explicit, independent suite as research evidence for the current host. Before using it as a release gate, agree whether "globe stays visible" means a mounted rendered globe or a recognizable uncovered part, and define a visual acceptance rule for the latter. Extend the inventory when kernels or routes land, then rerun against that exact revision. Preserve fresh-context replay and true keyboard traversal; keep placeholder coverage clearly distinguished from working scientific modules. Promote a reviewed suite through a separately authorized build task rather than editing protected CI from this research task.
