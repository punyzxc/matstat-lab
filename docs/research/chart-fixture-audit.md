## AC1: exact membership and right-continuous ECDF

**Fact — convention:** the current codec implements bins `[edge_i,edge_(i+1))`, with the last bin including the final right edge. Values below the first edge and above the last edge are counted separately. This agrees with NumPy's endpoint convention, but the explicit underflow/overflow accounting is a project choice. Source: [codec `validSeries`](../../spikes/explorer-chart/snapshot.mjs), [NumPy histogram documentation](https://numpy.org/doc/stable/reference/generated/numpy.histogram.html).

**Fact — empirical CDF definition:** for these complete uncensored samples, `F_n(q) = count(values <= q)/N`. At a tied observation the count includes **all** copies at that value; between distinct values it stays constant. Cumulative counts and probabilities have different scales: the stored sequence is counts, and the fraction is count/N. Source: [SciPy ECDF](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ecdf.html), [stored v2 scale](../../spikes/snapshot-comparison-fields/snapshot-v2.mjs). The independent query assertions test at the jump, immediately beside it, and between jumps; they do not merely compare a sorted list of coordinates.

**Fact — hand-counted fixture A (`ties-final-edge`):** all numbers in this table are literal witness values in [`fixtures.json`](../../spikes/chart-fixture-audit/fixtures.json), checked by the no-import oracle.

| Item | Exact expected value |
|---|---|
| Original observations, in order | `[-1, 0, 0.5, 1, 1, 2, 3]`, N=7 |
| Edges | `[0, 1, 2]` |
| Bin `[0,1)` members | `[0,0.5]`, count=2 |
| Final bin `[1,2]` members | `[1,1,2]`, count=3 |
| Underflow / overflow | `[-1]` / `[3]`, counts 1 / 1 |
| Conservation | `1 + 2 + 3 + 1 = 7` |
| ECDF distinct x | `[-1,0,0.5,1,2,3]` |
| ECDF cumulative counts | `[1,2,3,5,6,7]` |
| Counts at q = -2, -1, -0.5, 0, 0.75, 1, 1.5, 2, 3, 4 | `[0,1,1,2,3,5,5,6,7,7]` |

**Fact — additional independent witnesses:** the following expected values and query counts are fully enumerated in the same [fixture file](../../spikes/chart-fixture-audit/fixtures.json).

| Fixture | Input / edges | Bins; underflow, overflow | ECDF cumulative counts at distinct sorted values |
|---|---|---|---|
| `unequal-widths` | `[-2,-1,-1,0,1,1,2,4,5,6]`; `[-1,1,5]` | `[3,5]`; 1,1 | x=`[-2,-1,0,1,2,4,5,6]`, counts=`[1,3,4,6,7,8,9,10]` |
| `all-ties-empty-bins` | `[1,1,1]`; `[0,1,2,3]` | `[0,3,0]`; 0,0 | x=`[1]`, counts=`[3]`; count immediately below 1 is 0, at 1 is 3 |
| `all-outside` | `[-3,-2,4,4]`; `[0,1,2]` | `[0,0]`; 2,2 | x=`[-3,-2,4]`, counts=`[1,2,4]`; count within plot domain is 2, not 0 |
| `precision-near-edges` | See precision table below; `[0,1,2]` | `[2,4]`; 1,1 | Eight distinct x values; ranks `[1,2,3,4,5,6,7,8]` |

**Fact — normalization check:** the unequal-width fixture has N=10 and widths 2 and 4. Its count heights `[3,5]` have units “observations”; relative heights `[0.3,0.5]` are dimensionless; total-N density heights `[0.15,0.125]` have units `s^-1`. The density area is `0.15*2 + 0.125*4 = 0.8`, the visible fraction. This arithmetic is separately [tested](../../spikes/chart-fixture-audit/audit.test.mjs) and follows the [team's total-N density proposal](statistical-engine.md).

**Fact — reference-library distinction:** `numpy.histogram(..., density=True)` normalizes density over the retained histogram range, whereas this team's proposal includes excluded observations in N. Therefore do **not** blindly use NumPy's density=True values as this project's density oracle when there is underflow/overflow. NumPy count membership is usable; compute the declared total-N density separately. Source: [NumPy `range` and `density` definitions](https://numpy.org/doc/stable/reference/generated/numpy.histogram.html), [project proposal](statistical-engine.md).

**Assumption — coverage boundary:** these fixtures cover complete retained unweighted observations with finite binary64 values, increasing finite edges and count-scaled series. Empty observations, nonfinite values or non-increasing edges are rejected by this small oracle. Weighted/censored data, truncated retention, binned-only aggregates, log axes and approximate quantiles need separate witnesses; no claim about them is made here. The audit is not a replacement for the production schema validator or model-domain validation.

## AC2: mutations that conserve totals

**Fact — histogram mutation:** for `unequal-widths`, replace counts `[3,5]` with `[4,4]`, leaving edges, underflow=1 and overflow=1 unchanged. Both totals are 10 and both counts are nonnegative integers. The independent audit reports **only `histogram-membership`**; the ECDF remains correct. Source: [mutation test](../../spikes/chart-fixture-audit/audit.test.mjs).

**Fact — separate ECDF mutation:** replace cumulative ranks `[1,3,4,6,7,8,9,10]` with `[2,3,4,5,7,8,9,10]`. Both arrays are strictly increasing, end at N=10, and even have the same summed ranks (48). The independent audit reports **only `ecdf-ranks`**; the histogram remains correct. Thus neither final N, monotonicity, nor a summed-rank checksum establishes correct jumps. Source: [rank mutation test](../../spikes/chart-fixture-audit/audit.test.mjs).

**Fact — other isolated failures:** moving the tied-support coordinate 0.5 to 0.75 with identical ranks reports `ecdf-support`; moving the final-edge observation to overflow reports `histogram-membership` and `histogram-overflow`; reallocating underflow/overflow without changing N reports both outside-count errors. Changing sample size, edges, retained order/values, units or count/fraction/density labels has a distinct failure category. Source: [audit tests](../../spikes/chart-fixture-audit/audit.test.mjs), [independent oracle](../../spikes/chart-fixture-audit/oracle.mjs).

**Fact — existing codecs tested:** the merged v2 codec accepts all five correct witnesses and rejects the two equal-total bin/rank corruptions. No incorrect bin/rank acceptance was found on these cases. The existing codec can legitimately accept a **self-consistent replacement dataset** if both raw observations and charts are rounded and recounted together; it has no external access to the original observations. The external witness detects that replacement (`retained-values`, changed memberships/support). This demonstrates the need for an independent observation record; it is not a claim that a self-consistency decoder can authenticate original measurements. Source: [codec integration tests](../../spikes/chart-fixture-audit/codec-integration.test.mjs).

## AC3: exact retained values, units and presentation rounding

**Fact — saved precision witness:** the committed native-v2 [JSON fixture](../../spikes/chart-fixture-audit/saved-precision-v2.json) and legacy-column [CSV fixture](../../spikes/chart-fixture-audit/saved-precision-v1.csv) contain the following original values in this exact draw order. These decimal literals specify JavaScript binary64 values, not exact real-number measurements.

| Draw | Original numeric literal | Independent membership on edges `[0,1,2]` | Example display with 2 decimals |
|---|---|---|---|
| 1 | `-5e-324` | underflow | `-0.00` |
| 2 | `0` | first bin | `0.00` |
| 3 | `0.9999999999999999` | first bin | `1.00` |
| 4 | `1` | final bin | `1.00` |
| 5 | `1.0000000000000002` | final bin | `1.00` |
| 6 | `1.9999999999999998` | final bin | `2.00` |
| 7 | `2` | final bin, included endpoint | `2.00` |
| 8 | `2.0000000000000004` | overflow | `2.00` |

**Fact — checks actually run:** native-v2 decode preserves all eight binary64 values and the `s` unit; v1 JSON export preserves the raw values and original numerical series exactly. The corresponding v1 CSV export preserves all eight values, order and its five provenance fields. Assertions use exact integer equality and `Object.is`/strict deep equality for saved values, not a floating-point tolerance. Replacing `1.0000000000000002` with `1` fails even though the display is identical. Source: [integration tests](../../spikes/chart-fixture-audit/codec-integration.test.mjs), [oracle tests](../../spikes/chart-fixture-audit/audit.test.mjs).

**Fact — presentation-only rounding:** converting these original observations to two-decimal numbers changes the scientific dataset, collapses distinct ECDF steps and can change underflow/bin/overflow membership. The self-consistent rounded-replacement test demonstrates that the external witness still rejects it. Rounding is acceptable only for labels derived from the unchanged full-precision data; the tests do not assert that a screen displaying `1.00` proves a stored value is exactly 1. Source: [rounding mutation tests](../../spikes/chart-fixture-audit/codec-integration.test.mjs).

**Fact — metadata limitation found:** #4's actual CSV columns are `id,module,seed,rng_version,algorithm_version,draw,value`. There is no units column, distribution/parameter description, series definition, bin-edge declaration, or explicit file schema version. The audit returns `csv-units-missing`, while separately verifying values and provenance. “v1” in this fixture's filename denotes association with the v1 snapshot exporter, not a version marker present in the CSV. The native-v2 JSON carries units, series labels and parameters; migration of v1 JSON correctly leaves units unknown (`null`). Source: [CSV exporter](../../spikes/explorer-chart/snapshot.mjs), [v2 migration](../../spikes/snapshot-comparison-fields/snapshot-v2.mjs), [executed integration checks](../../spikes/chart-fixture-audit/codec-integration.test.mjs).

**Assumption — recommendation to the contract owner:** treat the current CSV as a **retained-draw table**, not a self-contained replay/audit envelope. Pair it with the versioned JSON record or an agreed metadata sidecar linked by record ID and digest. A future units column must be explicit and tested (the independent reader tests this proposed extension), not inferred from module name or old records. Unknown units must stay unknown. This task does not change the exporter or introduce an approved format.

**Fact — CSV audit limits:** the no-dependency reader handles quoted fields, escaped quotes, CRLF/LF and numeric scientific notation. It checks row width, required/duplicate column names, complete draw count, sequential draw IDs, finite numeric syntax, exact values, provenance and optional explicit units. It rejects empty/nonfinite numeric cells instead of converting blank to zero. It is intentionally a tiny-fixture audit, not an untrusted-file importer with streaming/resource/security guarantees. CSV format guidance: [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180). Implementation and tested cases: [oracle](../../spikes/chart-fixture-audit/oracle.mjs), [tests](../../spikes/chart-fixture-audit/audit.test.mjs).

## Position

**Assumption — proposed position:** require exact independent per-bin membership, ECDF support/ranks and retained-value comparisons; total counts and visually similar plots are insufficient. Retain full-precision values and explicit units with the snapshot, and mark a raw CSV's missing metadata honestly. These witnesses found no membership/rank defect in the merged codecs on the covered cases; they did expose CSV's lack of independent unit evidence and demonstrate why self-consistency alone cannot detect an already-rounded replacement dataset. The latter two are scoped audit limitations, not changes to the team's contract. Remaining uncertainty: the production schema, truncation/weighting policies and the approved self-contained export format.
